# 抓包指南：拿到 Cookie 和签到接口

整个项目只有这一步需要你手动做一次，大约 2 分钟。

官方没有公开签到接口，而且活动页会改版，所以项目不写死地址 —— 你自己抓一次，填进配置。

---

## 准备

- 一台装了 Chrome / Edge 的电脑
- 豆包电脑客户端已登录（或浏览器已登录 <https://www.doubao.com>）
- 如果签到入口只在客户端里，可以先用客户端点一次，看它打开的网页地址；只要那个页面在浏览器里能打开且已登录，抓包就能进行

---

## 方法一：用项目自带的抓包脚本（推荐）

这个脚本临时劫持页面的 `fetch` 和 `XMLHttpRequest`，把请求原样记录下来，不修改任何数据，刷新页面即失效。

### 1. 打开控制台

浏览器访问 <https://www.doubao.com>，确认右上角是已登录状态。

按 `F12`（或 `Ctrl+Shift+I`）打开开发者工具，切到 **Console** 面板。

> 第一次用可能会提示 "Warning: Don't paste code..."。按提示在输入框里手打 `allow pasting` 回车，然后才能粘贴。

### 2. 注入脚本

打开项目里的 [`tools/capture-snippet.js`](../tools/capture-snippet.js)，全选复制，粘贴到 Console，回车。

看到 `已开始监听，请回到页面点一下「签到」…` 就说明挂上了。

### 3. 触发签到

回到豆包页面，正常点一次「签到」。

### 4. 抄结果

Console 会自动清屏并打印：

```js
① 复制到 .env / GitHub Secrets 的配置：
{
  DOUBAO_CHECKIN_URL: "https://www.doubao.com/xxxxx/api/xxxx/checkin",
  DOUBAO_CHECKIN_METHOD: "POST",
  DOUBAO_CHECKIN_BODY: "{\"activity_id\":123}",
  DOUBAO_EXTRA_HEADERS: "{\"x-csrf-token\":\"...\"}"
}
② 接口原始响应（用来确认成功关键词）：
{"code":0,"msg":"签到成功，获得200活动额度"}
```

把 ① 里的四项填进 GitHub Secrets 或本地 `.env`，② 里的响应留着对照关键词。

### 5. 抓 Cookie

脚本不会打印 Cookie（避免你不小心截图泄露）。单独取一次：

1. Console 里执行 `document.cookie` —— 这只包含非 HttpOnly 的部分，**通常不够**
2. 更可靠的方式：切到 **Network** 面板 → 随便点一个请求 → **Request Headers** → 找到 `Cookie:` 那一行，右键 → `Copy value`
3. 或者在 **Application** → **Cookies** → `https://www.doubao.com` 下逐条复制，拼成 `k1=v1; k2=v2` 的格式

把完整字符串填进 `DOUBAO_COOKIE`。

> ⚠️ Cookie 等同于你的登录状态。不要贴到 Issue、聊天群、截图里。项目日志对它是脱敏处理的。

### 如果一条都没抓到

脚本靠 URL 关键词匹配，默认规则是：

```
/checkin|sign|signin|daily|task|reward|credit|quota|activity/i
```

如果没命中，把脚本第 12 行的 `PATTERN` 改宽，比如直接改成 `/./`（记录所有请求），重新注入后再点一次签到，然后在 `window.__doubaoCaptured` 里翻。

## 方法二：手动从 Network 面板找

不想跑脚本就用这个。

1. `F12` → **Network** 面板 → 勾上 **Preserve log**，过滤器选 **Fetch/XHR**
2. 点一次「签到」
3. 列表里会多出一条请求。逐条点开看 **Response**，找到返回里有「签到」「额度」「credit」「reward」字样的那条
4. 右键那条请求 → **Copy** → **Copy as cURL (bash)**
5. 从复制出来的 cURL 里取出：
   - `--url` 后面的地址 → `DOUBAO_CHECKIN_URL`
   - `-X` 后面的方法 → `DOUBAO_CHECKIN_METHOD`
   - `--data-raw` / `--data` 后面的内容 → `DOUBAO_CHECKIN_BODY`
   - `-H 'Cookie: ...'` 里的值 → `DOUBAO_COOKIE`
   - 其余非标准头（`x-*`、`referer` 等）→ `DOUBAO_EXTRA_HEADERS`，JSON 对象格式

---

## 填进 GitHub Secrets

仓库 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**。

| Name | 必填 | 示例 |
| --- | --- | --- |
| `DOUBAO_COOKIE` | ✅ | `sessionid=xxxx; sid_tt=yyyy; ...` |
| `DOUBAO_CHECKIN_URL` | ✅ | `https://www.doubao.com/xxx/api/xxx/checkin` |
| `DOUBAO_CHECKIN_METHOD` | 建议 | `POST` |
| `DOUBAO_CHECKIN_BODY` | 视接口 | `{"activity_id":123}` |
| `DOUBAO_EXTRA_HEADERS` | 视接口 | `{"x-csrf-token":"abc"}` |

填完去 **Actions** → **Run workflow**，把 `dry_run` 勾上先看一眼日志里的 URL 和请求体对不对，再跑真实的。

## 调关键词

如果日志显示 `签到失败` 但响应里明显是成功的，把响应贴进配置里对齐关键词。例如响应是：

```json
{"code":0,"data":{"status":1},"msg":"领取完成"}
```

三种调法，从精准到宽松：

```bash
# 1. JSON 字段判定（最准，推荐）
DOUBAO_SUCCESS_JSON_PATH=data.status=1

# 2. 自定义成功关键词
DOUBAO_SUCCESS_KEYWORDS=领取完成,成功

# 3. 已签到关键词（避免重复签到被误判成失败）
DOUBAO_ALREADY_KEYWORDS=今日已领,已经领取
```

改完 Secret 后手动跑一次验证。**这一步只需要做一次，之后接口不改版就不用再管。**

## Cookie 失效了怎么办

日志出现下面这行就是 Cookie 过期了：

```
[ERROR] Cookie 可能已失效（命中关键词：未登录）
```

1. 浏览器重新登录豆包
2. 按上面「第 5 步」重新取一次 Cookie
3. 到 Secrets 里更新 `DOUBAO_COOKIE`
4. 手动跑一次确认恢复

建议顺手配个通知通道（比如 Server 酱），这样 Cookie 一失效你当天就能知道，不会默默断签好几天。
