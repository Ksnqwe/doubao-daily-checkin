# 部署方式

项目是纯 Python 标准库，没有任何外部依赖，所以能跑 Python 的地方都能跑。

下面按推荐程度排列。

---

## 方案一：GitHub Actions（推荐，默认）

**优点**：不用服务器、不用开机、免费、仓库即备份。

仓库里已经配好了 `.github/workflows/checkin.yml`，Fork 后配好 Secrets 就能用。

### 时间设置

GitHub 的 cron 用 **UTC**，没有时区参数。

| 想要的北京时间 | cron 表达式 |
| --- | --- |
| 00:05 | `5 16 * * *` |
| 00:30 | `30 16 * * *` |
| 06:00 | `0 22 * * *` |
| 08:00 | `0 0 * * *` |

北京时间 = UTC + 8，所以「北京时间次日 00:05」=「UTC 当天 16:05」。项目默认就是这个，并额外加了一条 00:35 的兜底。

### 保持任务存活

GitHub 会在公开仓库连续 **60 天没有任何提交活动**后暂停其中的 scheduled workflow。项目里的 `keepalive.yml` 每月提交一次 `state/heartbeat.txt` 来规避。

如果哪天发现任务突然不跑了，检查两处：

1. 仓库 **Actions** 页顶部有没有 "This workflow was disabled" 的黄色提示 → 点 **Enable workflow**
2. 有没有超过 60 天没有 commit

## 方案二：本地 Windows 任务计划

适合不想把 Cookie 放云端、或者想同时管理多个账号的情况。

### 1. 准备

```bat
git clone https://github.com/<your-name>/doubao-daily-checkin.git
cd doubao-daily-checkin
copy .env.example .env
```

编辑 `.env`，填入 `DOUBAO_COOKIE` 和 `DOUBAO_CHECKIN_URL`。

先手动验证：

```bat
python main.py --check
python main.py
```

### 2. 创建计划任务

用管理员身份打开 PowerShell：

```powershell
$action  = New-ScheduledTaskAction `
  -Execute "pythonw.exe" `
  -Argument "main.py" `
  -WorkingDirectory "C:\path\to\doubao-daily-checkin"

$trigger = New-ScheduledTaskTrigger -Daily -At "00:05"

# 错过时间也补跑；只在有网络时执行
$settings = New-ScheduledTaskSettingsSet `
  -StartWhenAvailable `
  -DontStopIfGoingOnBatteries `
  -AllowStartIfOnBatteries

Register-ScheduledTask `
  -TaskName "豆包每日签到" `
  -Action $action `
  -Trigger $trigger `
  -Settings $settings `
  -Description "每天 00:05 自动签到领额度"
```

用 `pythonw.exe` 而不是 `python.exe`，这样不会每天凌晨弹一个黑窗口。

> 电脑关机/睡眠时任务不会执行。`-StartWhenAvailable` 会在唤醒后补跑一次，脚本本身幂等，补跑没风险。

### 3. 查看结果

```powershell
Get-ScheduledTaskInfo -TaskName "豆包每日签到"
```

或者直接看通知。本地运行建议配上通知通道，否则出问题你不会知道。

## 方案三：Linux / macOS cron

```bash
crontab -e
```

```cron
# 每天 00:05（服务器时区为 Asia/Shanghai 时）
5 0 * * * cd /opt/doubao-daily-checkin && /usr/bin/python3 main.py >> logs/checkin.log 2>&1
```

如果服务器是 UTC 时区：

```cron
5 16 * * * cd /opt/doubao-daily-checkin && /usr/bin/python3 main.py >> logs/checkin.log 2>&1
```

记得先 `mkdir -p logs`，并用 `timedatectl` 或 `date` 确认时区。

## 方案四：云函数 / 容器

因为零依赖，打包非常简单，把整个目录（除 `.env`）压成 zip 即可：

- **腾讯云函数 / 阿里云函数计算**：运行时选 Python 3.9+，入口设为 `main.main`，环境变量里配 Cookie 和 URL，定时触发器设 `0 5 0 * * * *`（各家 cron 格式略有差异）
- **Cloudflare Worker**：需要把逻辑改写成 JS，或者用 `workers-python` 之类的方案，不太划算
- **Docker**：基础镜像 `python:3.12-slim`，`CMD ["python", "main.py"]`，配合宿主机的 cron 或 `docker run` 的调度

云函数的公网 IP 和浏览器不同，部分接口可能因此触发风控。如果日志里出现 `RISK`，说明碰上了，换回 Actions 或本地运行。

---

## 怎么选

| 场景 | 推荐 |
| --- | --- |
| 就想省事，一个账号 | GitHub Actions |
| 不想把 Cookie 放云端 | 本地任务计划 |
| 有常开的 NAS / 小主机 | Docker + cron |
| 多个账号 | Fork 多份 Actions，或本地用不同 `.env` |

## 运行日志与排错

所有方案都建议先手动跑一次 `python main.py --dry-run`，确认请求构造正确。

常见状态码含义：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `SUCCESS` | 签到成功 | 无 |
| `ALREADY` | 今日已签到 | 无，属于正常 |
| `AUTH_FAILED` | Cookie 失效 | 重新抓 Cookie 更新配置 |
| `RISK` | 疑似风控 | 降低频率、换网络环境 |
| `FAILED` | 其他失败 | 看日志里的响应片段，调关键词 |

退出码：`0` 成功/已签到、`1` 失败、`2` 配置错误。可以直接用来做告警判断。
